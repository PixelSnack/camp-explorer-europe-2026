# Winter camps section: design (6 September 2026)

*Status: approved direction (owner, 6 Sept 2026: "full power forward as recommended"); spec written for review before the build. Author: ESC Claude. Audience of the feature: parents choosing a winter camp for their child on a live production site.*

## 1. Goal and non-goals

**Goal.** Give www.europeansummercamps.com a winter camps section that (a) catches winter demand in the September to November window, which is the summer directory's quiet season, (b) rides the existing domain's ranking instead of starting a new domain from zero, (c) sells Premium placements to winter operators on real traffic, and (d) is built so the winter data and copy can be lifted into a standalone site later without a rewrite.

**Non-goals for this build.** No separate domain site (the owner buys europeanwintercamps.com as a defensive registration and points it at the winter section). No change to the title tag, H1, meta description or the summer headline numbers. No winter filters beyond a count line (with five to eight listings, filters would be noise). Header backdrop: a generated Alpine ski-camp scene (owner request 6 Sept; `src/assets/winter-alpine-hero.{avif,webp,jpg}`, ledgered in docs/reference/GENERATED_ASSETS.md) with the same gradient overlay and picture element pattern as the summer hero.

## 2. Data

- New file `src/data/winterCamps.js` exporting `winterCamps`, an array with the same shape as `allCamps` plus `season: "winter"`. Same rules: per-child price with unit and provenance comment, `dates` under about 40 characters, `bookingStatus` only when verified, `rating: null, reviews: 0` unless reviews are verified, tested https `bookingUrl`, one `category` value `"winter"`.
- IDs continue the shared sequence (next free after 70, which is reserved for ILC), so comparison keys and `data-camp-card` stay unique.
- `allCamps` keeps meaning the summer directory. Every summer-derived number (marquee, hero stats, footer, About, Guide, filter counts, `countryList`, `AGE_SPAN`, sitemap caption) is untouched. The winter view derives its own count and country count from `winterCamps`.
- Booking badge: same `getBookingBadge` rules. Winter rows carry `bookingStatus: "open"` only when registration is verified open (provenance comment with date), otherwise no field; the validator rejects any other winter value. The winter season is its own constant in `src/data/season.js` (`WINTER_SEASON = '2026-27'`), independent of `SEASON_YEAR`.
- Publication flag `WINTER_PUBLISHED` in `src/data/season.js` gates every promotional entry point together (menu item, home teaser, ItemList entry); the `#winter` hash renders regardless so the view can be tested dark. The FAQ entry ships in the same release as the flag flip.
- `scripts/validate-camps.js` runs the same per-camp checks over `winterCamps` and additionally: one global ID set across both arrays (duplicates within either array fail); `season === "winter"` and `category === "winter"`; required card fields non-empty (name, location, country, ages, price, dates, type, activities, highlights, languages, image); `dates` at most 40 characters for winter rows; winter `bookingStatus` limited to `"open"`; `reviews > 0` on a winter row requires `reviewData`; at most three `featured` rows per category across both arrays. It also snapshots the protected metadata: the exact title, og:title and twitter:title strings derived from `SEASON_YEAR` must match, so no winter work can drift them.

## 3. Routing and navigation

- `winter` joins `KNOWN_SECTIONS`; the view renders when `activeSection === 'winter'`, hash `#winter`.
- Menu item "Winter Camps" in the desktop nav and the mobile menu, placed after "Discover Camps". Breadcrumb entry "Winter Camps".
- Entry points are the menu, the teaser button, the initial hash and browser history. The hash handler applies `?search=` and `?category=` parameters only when the section is `discover` or `home`, so `#winter?category=sports` cannot change summer filters. No filter state is changed on entering winter; a parent returning to Discover finds their filters intact. The filter drawer is closed on navigation.

## 4. The winter view

- Header block: the generated backdrop with the summer hero's dark gradient overlay, H2 "European Winter Camps", one intro paragraph (residential ski and snowboard camps and winter sports schools, December to April, booked for one child), a season line with no unverified claim ("Dates and prices are shown for the 2026-27 winter season as published by each operator"), and the count line "N winter camps in M countries". The summer `SeasonNotice` is not reused.
- Grid: the same card as the Discover grid. To avoid a third copy of 200 lines of card markup, the Discover card is extracted into a `CampCard` component with no visual change; the Winter grid reuses it. Dependency inventory before extraction: `camp`, `isSelected`, `onToggleCompare`, `onBook`, `onVideo`, `mapCompressed` fallback class, alt and title text (parameterized by season: "summer camp in" stays for summer rows, "winter camp in" for winter rows), the React key and `data-camp-card` on the root, and every class string. Featured-first sorting stays in the parent and is applied to the winter grid too. The Home grid markup is left untouched (indexed view; zero-touch rule); its inline booking and video handlers call the same shared functions.
- Empty state: if `winterCamps` is empty the view shows the header and an undated "Winter listings are being verified" line. `WINTER_PUBLISHED` flips only when at least four winter camps are verified STRONG; candidate names never count as inventory.
- The filter FAB stays hidden on the winter view (no winter filters in this build); the winter grid renders from `winterCamps` directly, never from `filteredCamps`. The scroll-to-last-camp button keeps working because only one grid is mounted at a time and cards carry `data-camp-card`.

## 5. Crawlable surface (the SEO part that matters)

Hash views are invisible to crawlers, so the winter content that Google can read must live on the home view and in index.html:
- Home view: a short "Winter camps" teaser section between the FAQ and the footer: H2, two sentences, a button to `#winter`. This is the only crawlable winter text and it is written for the query "winter camps europe" without touching the summer H1 or title.
- FAQ: one new entry "Are there European winter camps for children?" in `src/data/faq.js`, mirrored into the FAQPage JSON-LD in index.html (the build fails otherwise).
- JSON-LD: the WebSite `mainEntity` ItemList (a list of the directory's sections, not of camps) gains an eighth `ListItem` "Winter Camps" pointing at `#winter`; `numberOfItems` becomes 8. The Organization `knowsAbout` array gains "European Winter Camps" and "Ski Camps for Kids". The static BreadcrumbList is left unchanged; the runtime breadcrumb gets a Home to Winter Camps entry.
- Sitemap: unchanged (single URL). A real `/winter` URL is a Phase 2 item.
- Title, meta description, og tags, H1: unchanged. Protecting the head terms outranks winter.

## 6. Analytics and Premium

- Booking and video instrumentation is centralized: `trackOutboundClick`, `handleBookingClick` and a new `handleVideoClick(camp)` are the only places that fire `camp_booking_click` and `video_click`, each with `camp_season` set to the camp's season or summer by default; Home, Discover, Compare and Winter all call them, so exactly one event fires per action and UTM values are unchanged. `window.open` stays synchronous in the click handler for iOS. Registering `camp_season` as an event-scoped custom dimension in GA4 is an owner dashboard item.
- Premium works unchanged (`featured: true`, badge label by price class, video button, featured-first sort in the winter grid). The cap of three paid slots applies to the winter section as one category and is validator-enforced; a budget-priced featured listing still consumes a slot.

## 7. Copy rules

- Em-dash ban, no X-not-Y formulas, no tricolons, no numeric claims without a source. Booking-timeline wording must be true for winter camps (owner rule, 17 Aug 2026). Do not undersell the verification work; the FAQ answer names the five-point test.

## 8. Verification and rollout

1. Content first: at least four winter camps verified STRONG on all five points (Les Elfes Winter is the anchor; UCPA, La Garenne and the Finnish operator are candidates; German resellers are excluded by construction). Each number checked by the lead on the operator page; La Garenne's fee table needs a real browser.
2. Build in three commits: data plus validator; `CampCard` extraction with a before/after DOM diff of the Discover grid (no visual change); the winter view, nav, home teaser, FAQ and JSON-LD.
3. Reviews (owner rule 6 Sept: the lead orchestrates, a primary Fable review comes first, Astra is the second opinion): the lead's own full review of the complete diff (CampCard, validators, data, analytics, JSON-LD), a Fable enterprise-code-reviewer pass on the same diff, then a GPT-6 Astra adversarial pass; the Gemini SEO opinion on the teaser and FAQ copy is already on record. Every finding adjudicated in this document.
4. Gates: build with both validators, lint, headless-Chrome checks at 320, 390, 768, 800, 1024 and 1440 (winter view, Discover before/after DOM diff, home teaser, header nav with the extra item at the md breakpoint, longest winter date and price strings, all hash routes including `#winter?category=sports`, console clean), the owner's iPhone check for Safari, then production visual check via Claude in Chrome after the push.
5. Rollback, two paths, both tested before the push: (a) winter exposure only, flip `WINTER_PUBLISHED` to false (one-line commit); (b) extraction regression, revert the `CampCard` commit and the view commit together. Tag the last known-good release before the first winter commit. Monitoring: the weekly GSC watch adds the displayed title link and the summer head-term positions against the pre-release baseline.

## 9. Later, not now

Separate domain when winter passes about ten listings and Phase 2 (React Router plus SSG) gives `/winter` a real URL; a generated winter hero image; a "2026/27 dates published" badge label; winter-specific filters; migrating the Home grid to `CampCard`.

## Decisions recorded

- On-site section over a new domain now: the domain's authority and the September-to-November window decide it; the defensive registration keeps the name.
- Separate data file over a `season` field on `allCamps`: zero regression risk for every summer-derived number and a clean extraction path.
- Hidden filter toggle rejected: no crawlable surface, nothing to sell, muddied counts.

## Adjudication of the external reviews (6 September 2026)

**GPT-6 Astra, adversarial spec review (effort high, 16 findings).** ACCEPTED and folded into the sections above: hash query parameters applied only on discover/home (HIGH); FAB excluded from winter and the grid rendered from `winterCamps` (HIGH); CampCard dependency inventory, season-parameterized alt text, sorting in the parent (HIGH); validator additions for global IDs, required fields, winter status vocabulary, review evidence on winter rows, featured cap, and exact protected-title snapshots (HIGH); winter season constant, removal of the unsupported "most winter camps" claim, undated empty state (HIGH); breakpoint-adjacent widths and the owner's Safari check (HIGH); centralized booking and video instrumentation with `camp_season` (HIGH); featured-first sort and cap in winter (MEDIUM); ItemList as a section list, static BreadcrumbList untouched, `knowsAbout` additions (MEDIUM); two rollback paths and a known-good tag (MEDIUM); one publication flag for all promotional entry points (MEDIUM). PARTIALLY ACCEPTED: the comparison "BLOCKER" assumed ID lookups; `selectedCamps` already holds camp objects, so cross-season comparison, the shared limit of three and removal work without a registry; accepted only the test of one camp from each season and the season label on the compare card. REJECTED with reason: scoping the scroll-to-last-camp lookup (only one grid is ever mounted); requiring `reviewData` on summer rows (39 rows carry legacy counts pending the review-aggregation Phase 2; enforced for winter rows only); mapping an empty hash to Home (pre-existing behaviour on the summer routes, out of scope for a winter change, logged as a separate item). DEFERRED: GA4 custom-dimension registration (owner dashboard); the defensive-domain redirect mechanics (owner buys the domain; a 301 to `/#winter` keeps the fragment in browsers, test on setup); a per-camp five-point evidence record in the validator (kept in the verification report instead).

**Gemini 3.8 Flash, SEO second opinion.** ACCEPTED: very low dilution risk with the teaser below the FAQ and above the footer; contextual button label "View European Winter Camps"; no "winter" in the title or meta description; ski-camp and school-holiday query families first, hockey last; `knowsAbout` additions; a real photo with descriptive alt text in the teaser; keep summer primary in the ItemList; never hide winter cards in the DOM. ADJUSTED: its H2 draft ("Winter Camps in Europe and Ski Camps for Kids") reads as keyword stacking; the H2 is "Winter Camps in Europe" and the sentences carry "ski camps for kids"; "continuous supervision" is a safety claim and becomes "supervised"; "across the Alps" is used only if every listing is Alpine. REJECTED with reason: the claim that an HTTP redirect drops the URL fragment (browsers preserve a fragment given in the Location header; verified at setup rather than assumed).

**GPT-6 Astra, diff review of Tasks 1 to 4 (6 September 2026, evening): no BLOCKER or HIGH; 4 MEDIUM, 3 LOW.** ACCEPTED and landed in the follow-up commit: the filter drawer now also closes when the section changes through the hash handler (back/forward, typed hash); validator requires every activities, highlights and languages element to be a non-empty string and `image` to resolve to a non-empty string; winter `price` must carry exactly one slash so the unit renders on the card; winter hero overlay darkened to 70/55/70 with white body copy (winter-only classes, summer hero untouched); `winterCountryCount` trims country names. ACCEPTED AS RECORDED, no code change: the `#winter` hash is a public preview while the flag is off; winter rows are only ever added in the publish commit that flips the flag, so no unpromoted booking buttons become reachable. DEFERRED: order- and quote-independent parsing of the protected title tags (index.html is authored with a stable attribute order; a formatting-only failure would be obvious and cheap to fix). Astra's clean list (summer filtering and sort, key on the mapped component, comparison wiring, one video path with camp_season, noopener on both popups, validator ID and cap logic, indexed Home untouched) matches the lead's own review. Release checks it asked for: a DevTools click test for one booking event per click is run before the push; the real-iPhone popup check is the owner's.
